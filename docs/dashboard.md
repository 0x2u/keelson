# The dashboard

The dashboard is a web application (Next.js, React, TypeScript) for one operator to control and observe every server. Agents deploy, health-gate, roll back, run jobs and send alerts on their own, so nothing breaks when the dashboard is off. This page describes what it shows and does. Installing and securing it is in [Hosting](./hosting.md), and the interface rules are in [UI guidelines](./design.md).

## What it shows

- **Servers**: an overview of every server with its health, and a page per server with its apps (what they serve and their last deployment), every container with its state and health, scheduled jobs and recent deployments. A container shows live CPU, memory, network and process statistics and a live, filterable log. An app has a deploy dialog, a rollback and its history. A deployment shows its log as it happens, drawn as the pipeline *Source → Build → Release → Switch → Soak → Live*. A job lists its runs with their output and has a *Run now*.
- **Projects**: one card per project (its live address, whether it is up, the commit that serves or is being deployed, a chip per environment) and a page per project. The page lists production first, then the other environments, the latest deployments and builds, and whether the last deployment failed while the previous version still serves. The verbs are **Deploy**, **Roll back** and **Promote** (staging to production, with the exact image).
- **Jobs, Databases and Activity** across all servers. Activity is one feed of deployments, job runs, backups, alerts, the agents' audit entries and the dashboard's security events, filterable by kind, server, app, failures and period. An alert row shows its title, severity, server and app, and how its delivery ended: delivered, partly delivered (the failed channels are named), not delivered, not sent (no channel is set up), dropped, or suppressed by the cooldown. The list is the last 200 notifications each server keeps. A server on an older agent lists none, and a server whose history cannot be read says so. If a server's most recent alert was not delivered (or only partly) in the last 24 hours, Home and the sidebar flag it as needing attention.
- **Fleet resources**: on wide screens the Servers list shows each server's disk, memory (used share) and load (per CPU) next to its status. They are coloured like the server's own verdict (from 85 % worth a look, from 95 % urgent; load from 1 per CPU), with a dash when the agent reports no value. Home shows the same three numbers on each server's card. The dashboard's thresholds are fixed. An agent alerts at the `disk_alert_percent` and `memory_alert_percent` of its own notification settings.
- **Readiness**: a checklist per project and per server, computed from facts the agent keeps: a backup configured, a restore tested, an off-site copy, the encryption key proven, an alert channel tested, a health check, a rollback target, a second factor on the dashboard, matching versions, and the dashboard's own state backed up.
- **A command palette** (`Ctrl+K` or `⌘K`) jumps to any page, project, server, app, domain, job, database or container. It also opens the dialog of an action (deploy, roll back, run a job, restart, start) with the target already chosen, but never acts by itself. `g` then `h`, `p`, `s`, `d`, `j` or `a` goes to a page, and `?` lists the shortcuts. There are light and dark themes.

## Connecting GitHub

Three pieces, each optional, set under *Settings → Integrations*:

- **A token** (read-only, plus an optional commit status). Paste a fine-grained token with read access to Contents, Actions and Metadata on the repositories you deploy. It is stored encrypted, checked against GitHub before it is saved, and only used from the dashboard's server. The only thing Keelson writes to GitHub is commit statuses: `keelson/preview` for a preview and `keelson/build` for a build (they need *Commit statuses: read and write*; without it previews work and no status is posted). An app's **Source** page then links the app to its repository and branch and shows the latest commits in one table with their CI result and what happened to each on this server (serving, deploying, deployed before, deploy failed), the commit currently serving and how many commits it is behind the branch, and the latest workflow runs. A commit is matched to a deployment when the image is tagged with its SHA (what `${{ github.sha }}` gives in CI); an image tagged otherwise, or deployed by digest, is shown as not matching a commit. **Deploy** on a commit rolls out that commit's image, and is disabled while its CI failed or is unfinished, while another deployment runs, or without a deploy secret. Answers are cached for 30 seconds to stay under GitHub's hourly quota.
- **A webhook** for automatic deploys when a CI workflow succeeds, and for previews: [Hosting](./hosting.md#github-webhook-automatic-deploys-and-previews).
- **A GitHub App** so that the agent builds and deploys each push or pull request without a CI workflow, and so that an app can be added from a repository: [Hosting](./hosting.md#github-app-build-and-deploy-from-pushes-and-pull-requests) and [Add an app from a repository](./hosting.md#add-an-app-from-a-repository). The App needs the dashboard to have an https address (`KEELSON_PUBLIC_URL`, set by the installer's `--domain`); without GitHub, **New project → From an image** deploys a ready-made image, see [Add an app from an image](./hosting.md#add-an-app-from-an-image).

## Other features, documented with hosting

- [Domains](./hosting.md#domains-cloudflare-dns-and-domain-checks): Cloudflare DNS records and live DNS, HTTPS and certificate checks while an app is added. The HTTPS check warns when the certificate has 14 days or fewer left and fails at 3 days or fewer (or once expired): the proxy renews certificates itself, so check that ports 80 and 443 are reachable and that DNS points at the server.
- [Environment variables](./hosting.md#environment-variables-write-only): add, replace, delete or import a `.env` file for an app (and for its previews) without SSH. Values are write-only once saved; agent-side storage is in [Environment variables and secrets](./reference/environment.md).
- [API tokens](./hosting.md#api-tokens-rest-api-and-mcp): scoped, expiring tokens for scripts, CI and the [MCP server](./mcp.md).
- Notifications: *Settings → Notifications* edits the agent's notification settings across servers ([Notifications](./reference/notifications.md)).
- Server settings: configuration editing (forms and a YAML editor with validation, diff and versions), updating the agent, and removing a server ([Servers](./reference/servers.md)).

## Versions

Releases are tags `vX.Y.Z`, and the agent and the dashboard in an image carry the same one (`v0.1.0`, or `v0.1.0-3-gabc1234` between tags, `-dirty` for a local change, `dev-<hash>` with no tag). The dashboard compares versions as semver. An agent older than its dashboard is offered the update. An agent newer than its dashboard is not, and the dashboard says to update itself first. *Settings → About* shows the dashboard's own version.

The dashboard's security model is in [Security](./reference/security.md).
